## 0.8.15

接着 0.8.14 继续查「没动任何文件，确认却说失效」。这一版把最后几条误判路径全部堵掉。

### 查到的事实

`12:20–13:10` 之间，三个被监视仓库**一个文件都没被修改**，但两份确认照样在 13:01 被判失效。所以这不是「文件变了」，而是程序把**「这一轮没能看到仓库」**当成了**「仓库变了」**。

真正会这么判的三条路径，旧版一条日志都不留：

- 仓库路径解析失败（`realpath` 一时失败：盘符忙、被杀毒或索引服务短暂占用）
- 文件监听器报错（大型仓库递归监听偶发失败）
- 状态目录监听器报错（一报错就把所有仓库一起作废）

### 现在的规矩

**作废只有一个理由：你批准的文件内容真的变了。**

- 解析不出路径：跳过这一轮，确认保留，记一行日志
- 监听器出错：丢掉监听改用轮询，确认保留
- 状态监听出错：只清追踪，不碰确认
- 文件被写入但内容一模一样：不算改动（以前写回相同内容也会误杀）
- 文件监听到覆盖范围内的动静：只触发一次复查，由**内容哈希**做最终判决

提交前 `commit()` 仍会独立校验一次，所以放宽这几条不会放进不该提交的东西。

### 可追溯

每次作废都会写一行来源到面板日志，并在窗口提示里带出文件名，例如：

```
[作废] D:\project\3 来源=poll 细节=src/app.mjs
```

来源只可能是 `poll`（内容比对确认真实变化），不再有环境原因冒充。
