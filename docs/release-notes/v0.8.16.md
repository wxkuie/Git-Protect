## 0.8.16

修一个**让确认按钮失效**的死锁。

### 现象

弹窗出来以后放一会儿，窗口还显示「可以提交」，点确认却报 **「版本已变化，旧确认失效」**，反复点都没用，只能关掉重来。

### 原因

`version` 这个字段里含索引文件的哈希。只要有任何外部 git 进程刷新过一次索引缓存（终端里 `git status`、编辑器/IDE 刷新、脚本跑一次 git），索引字节就变了，`version` 随之变化——但文件内容一个字没改。

而弹窗的判断和提交的判断用的不是同一把尺子：

- 弹窗每 3 秒调 `validate()`：版本变了但内容没变 → 放行，按钮保持可点
- 点确认调 `commit()`：直接严格比对版本 → 抛错，永远失败

于是窗口可以点、点了必失败。

### 修复

让提交用和校验相同的判定：**版本变了、且内容真的也变了**才拒绝。内容没变（只是索引被刷新）就正常提交。

弹窗期间真的改了文件，仍然会被拦下——这条门禁没有任何放宽。

### 回归

新增一条用例：批准 a.txt 后，去碰一个「没被批准、内容也没改」的已跟踪文件的 mtime，再让外部 git 刷新索引，然后 `validate` 必须通过、`commit` 必须成功。

移除修复后这条用例精确失败在 `commit` 的「版本已变化」，恢复后通过。全量 39 条通过。
