## 0.8.19

这一版把「日志」页重做成「活动」页。原来的日志页只有两块：自动提交记录（只记自动/静默模式的提交和上限提示）和原始监视输出；remind 模式下你点确认的提交、跳过、稍后、作废都不会留下记录，所以页面看起来什么都没用。现在它先回答「为什么没提醒」，再给出「最近发生了什么」。

### 1. 「现在为什么没提醒」摆在最上面

每个项目一行，直接说出挡住提醒的原因：

- 运行标记未结束（token + 已持续多久；超过 12 小时标「疑似残留」）
- 提交未收尾（事务门禁还在）
- 需人工核对（有恢复记录）
- 稍后提醒中（到几点）
- 本次不提交（这个版本已经跳过）
- 冷却中（到几点）
- 未配 git 身份 / 分支不符 / 读取失败 / 已停用
- 等停手（还差几分钟）/ 可提醒 / 没有改动

数据来自监视器用的同一份状态（`stateBlockers` 只读状态目录，不额外拉起 git 进程），不是界面猜的。

### 2. 运行标记可以一键收尾

外部自动化用 `guard begin` / `guard end` 占住仓库；如果它 begin 完忘了 end，这个仓库就永远不提醒——而且原先一行日志都不会写，用户只能干等。0.8.19 起：

- 活动页列出每个未结束标记的 token、开始时间、已持续多久
- 提供「收尾」按钮，只删除指定 token，不改其它状态
- 超过 12 小时标成「疑似残留」，提醒你处理，但不会自动删（删闸是安全动作）

真实案例：项目1 的 `p1-t025-restored-r2-20261127` 从 11-27 16:25 一直挂到 11-29 00:59（32 小时），期间一次都没提醒。

### 3. 活动记录

新增 `%APPDATA%\git-quiet-helper\state\activity.jsonl`，append-only，记录：

确认提交、弹窗提醒、本次不提交、稍后提醒、直接关窗、确认失效、提交收尾清理、运行标记开始/结束、监视启动/停止、自动提交上限降级、自动提交失败。

窗口退出码 0 既可能是「提交成功」也可能是「直接关窗」，用 `result-<repo>.json` 的落盘时间区分，不会把成功记成一次关窗。

### 4. 顺带

- 原始监视输出折叠到页面底部「原始监视输出（排查用）」，不再占主位
- 修掉活动列表里时间变量漏 `var` 造成的隐式全局
- 项目页新增「运行标记未结束」「需人工核对」两种状态
- 刚发现的措辞问题：刚开始的标记不能显示成「已 1 小时」，改为「已 N 分钟」
