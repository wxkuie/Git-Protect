## 0.8.18

修 6 个 P1 问题，外加一个只有打包版才会暴露的面板状态目录错位。0.8.17 没有发布：自检时发现恢复对齐的比较漏了索引的 stage 字段，有旧索引残留时对齐校验会必然误报失败、门禁清不掉。本版一并修掉，并把这个场景补成两条回归。正常提交流程不变。

### 1. 恢复清理不再覆盖你之后重新暂存的内容

`clearRecovery`（面板「处理」按钮、`guard recover --clear`）原先直接 `git reset HEAD -- <路径>` 修索引。如果提交其实已经落地、你在失败后又重新暂存了同一路径，这一步会把你的暂存内容换成 HEAD 版本。

现在事务里会记下「提交前这些路径在索引里的条目」，清理时逐路径比对：

- 还是提交前的旧值 → 安全对齐到 HEAD
- 已经变了（你重新暂存过）→ 原样保留

（0.8.18 修：对齐后校验时，树条目和索引条目要按同一种格式比较，否则「修好了」也会被误判成失败。）

### 2. 索引没修好时不再谎报「已清理」

索引对齐失败时，原先仍会删掉事务文件并返回 `cleared: true`：门禁消失了，旧索引还在，之后可能把旧内容当成新改动提交。

现在索引修不好就保留事务门禁，返回 `cleared: false` 和具体原因，面板如实显示「没能自动清理」。

### 3. 准备提交期间新增的 hook 会被拦住

版本比对只看文件内容，新增 `pre-commit` 之类的 hook 不在比对范围里。初始检查通过后、最终快照前临时放一个 hook，原先会一路执行。

现在最终检查同时比对 hook 列表与阻断原因：新增 hook 直接阻断，hook 不会被执行。

### 4. 接管旧窗口后不会永久占住仓库

应用重启时会把仍然开着的旧弹窗接管过来。但接管的窗口不是本进程的子进程，拿不到退出事件——用户关掉它之后 `open` 永远为真，这个仓库再也不会提醒。

现在接管时记下窗口 PID，每轮轮询；窗口退出就按「直接关窗」收尾，释放仓库。

### 5. 面板写接口要求本机来源

面板只监听 127.0.0.1，但任意网页都能用「不触发预检」的简单请求改配置、启停监视。现在：

- `Host` 必须是本机面板地址（挡 DNS rebinding）
- 带 `Origin` 时必须同源
- POST 必须 `Content-Type: application/json`

浏览器里正常使用不受影响。

### 6. 安装脚本不再误删目标目录

`install.ps1 -Target` 原先对已存在目录无条件递归删除。现在：

- 拒绝「目标 = 安装包目录」「目标在安装包里面」「目标是安装包上级」
- 目标已存在时，必须同时有 `GitQuietHelper.exe` 和 `uninstall.ps1` 才认作旧安装，否则拒绝并提示换目录

### 7. 打包版面板能看到并清理事务门禁

打包后的面板进程一直读安装目录的 `.state`，而监视器写的是 `%APPDATA%\git-quiet-helper\state`。结果是监视器留下的提交事务门禁在界面上既看不到也清不掉。

现在面板、状态线程、监视器统一用同一个状态目录。
